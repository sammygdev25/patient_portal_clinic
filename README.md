# Patient Portal Clinic

Clinic patient portal for booking appointments, visit notes, prescriptions, bills and documents with role-based access for patients, doctors and receptionists

## Run it with Docker

```bash
SECRET_KEY=$(python3 -c "import secrets; print(secrets.token_urlsafe(50))") docker compose up --build
```

Open http://localhost:8000. docker-compose.yml runs the production image against PostgreSQL on this
machine, and the app applies its migrations when it starts.

## Develop without Docker

You need Python 3.12, Node 20 and PostgreSQL. With DEBUG=1 the app uses
postgresql://app:app@localhost:5432/app unless DATABASE_URL says otherwise.

```bash
cd backend
pip install -r requirements.txt
DEBUG=1 python manage.py migrate
DEBUG=1 python manage.py runserver 8000

# in a second terminal
cd frontend
npm install --legacy-peer-deps
npm run dev
```

`./start.sh` does all of this in one go (Shikshya's preview runs it); with SEED_DEMO=1 it also loads the
demo data and this app's demo sign-ins, whose passwords are in backend/.env.

## Deploy

**Shikshya Cloud**: the Deploy button in Shikshya puts the app on Railway and sets everything below.

**Railway, on your own account**:

1. Create a project from this repository. Railway builds the Dockerfile.
2. Add a PostgreSQL database (Railway's Postgres template; Railway names the service `Postgres`).
3. In the app service's Settings, Networking, generate a domain. Railway sets `PORT` itself.
4. In the app service's Variables, set:
   - `DATABASE_URL` = `${{Postgres.DATABASE_URL}}`
   - `SECRET_KEY` = a long random string (`python3 -c "import secrets; print(secrets.token_urlsafe(50))"`)
   - `ALLOWED_HOSTS` = your domain, for example `myapp.up.railway.app`
   - `CSRF_TRUSTED_ORIGINS`, `CORS_ALLOWED_ORIGINS` and `PUBLIC_URL` = `https://` and that domain
   - leave `DEBUG` and `SEED_DEMO` unset: production runs with DEBUG off and gets no demo accounts
5. Deploy. The app applies its migrations when it starts and answers `/health/ready/` once the database
   is up.

Uploads (the pictures staff add) go to a storage bucket: in Railway, Create, Bucket, then set the app's
`STORAGE_BUCKET`, `STORAGE_ENDPOINT`, `STORAGE_ACCESS_KEY_ID`, `STORAGE_SECRET_ACCESS_KEY` and
`STORAGE_REGION` to references to the bucket's `BUCKET`, `ENDPOINT`, `ACCESS_KEY_ID`, `SECRET_ACCESS_KEY`
and `REGION` (for example `${{uploads.BUCKET}}`). Without a bucket they stay on the container's disk,
which every redeploy replaces.

A Shikshya Cloud deploy starts with the sample data and this app's demo and staff accounts: change those
passwords, or replace the accounts, before real customers sign in.

## Stack

- Backend: Django 5.2 LTS, Django REST Framework, daphne
- Frontend: React 18 with Vite
- Database: PostgreSQL
- Sign-in: expiring tokens (django-rest-knox)
